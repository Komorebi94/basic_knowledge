## 四项优先补强

1. **明确练习实际能力，并提供真实类型练习。** E25—E40 的状态、路径、窗口、预算等题按实际 JavaScript 能力命名，E31 不再冒充 React Hook，E33 不再冒充工具类型实现，E34 明确只验证事件名称和参数数量。K03-05 增加事件名与参数载荷的判别元组练习；K03-06 增加映射类型、只读约束、递归解包、联合与 null 的编译练习，包含正向代码、负向类型断言以及 Readonly 不等于冻结的运行时对照。
2. **补真实 React 行为。** K07-03—08 增加真实挂载的 key 重排、共享状态与初值副本、StrictMode 订阅清理与独立 Hook 状态、Suspense 首次及再次挂起、错误边界、Transition 保留内容、memo 与 Profiler。说明 startTransition 回调立即执行、await 后更新标记和竞态；React 19 use 的条件/循环例外单独说明。普通 SSR 用于对照 RSC，Server Function 引用的协议例外同步到正文和卡片。
3. **补服务端和架构的可执行路径。** K14-03—08 增加真实 Node pipeline 背压、取消和失败销毁，本机 HTTP BFF 的权限拒绝、503 部分失败与超时取消，React 流式 SSR 与 hydrateRoot 接管前后点击，可信会话分区缓存与退出拒绝，Node 临时文件生命周期探针。冷启动按托管生命周期建模，不再按 edge/Node 名称推断。K13-08 补可复算的 UTF-8 字节量、总量、分页、峰值请求和在途量估算。
4. **明确可观测性关联。** 日志和 trace 使用请求上下文，指标按路由模板等有界维度聚合；区分 requestId、traceId、spanId 与 exemplar。真实 AsyncLocalStorage 并发案例验证上下文不会串线，两个请求累计为一条指标序列。正文、练习要求和回忆卡不再要求指标携带每请求唯一 ID。

React 作者示例通过单独的本机运行时夹具执行，Node 示例在验证进程执行。这些验证没有扩大读者代码运行权限，也没有把读者提交放到主页面执行。没有新增依赖。
