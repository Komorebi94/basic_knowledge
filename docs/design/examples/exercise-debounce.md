# 防抖与取消

> E01 · 进阶 · 25 分钟 · P0 · JavaScript Worker  
> 关联 K01-02、K02-01、K12-02。以下是本题合同，刻意不覆盖所有工具库变体。

## 目标与接口

设计 debounce(fn, waitMs)，返回可调用包装器 wrapped。wrapped 同时具有 cancel() 和 flush()。只实现 trailing，调用结束安静一段时间后触发；不实现 leading、maxWait、Promise 聚合或构造调用。

fn 必须为函数，waitMs 为 0—2,147,483,647 的有限整数；否则创建时抛 TypeError 或 RangeError：非函数/非数字为 TypeError，数字非有限、非整数、越界为 RangeError。参数校验不启动任何计时器。

每次调用 wrapped 都以这次的 this 和全部参数替换待执行上下文，并重设等待时间。wrapped 始终返回 undefined，不承诺返回将来的调用结果。只考虑普通函数调用，不支持 new。

cancel() 清除待执行项、计时器、参数与 this 引用，返回 undefined；无待执行时是幂等空操作。flush() 有待执行时立即执行一次 fn，返回该次结果；没有待执行时返回 undefined。flush() 触发 fn 抛错时，同步将错误交给调用方。

定时器正常触发时，fn 抛错按宿主回调异常处理，不吞掉；触发前必须先清理本轮待执行状态，避免异常造成计时器或引用残留。

fn 执行中若再次调用 wrapped，该新调用属于下一轮；当前 flush/定时器回调结束不能把新一轮计时器误清掉。每个包装器实例互不影响。

## 三个可见样例

1. wait=100 ms；t=0 调用 A，t=50 调用 B，t=149 尚未执行，t=150 仅以 B 的参数执行一次。
2. wait=100 ms；t=0 调用 A，t=80 cancel，推进到 t=200，fn 未执行。
3. wait=100 ms；t=0 调用 A，t=40 flush，立即以 A 执行且返回结果；推进到 t=100 不再执行第二次。

## 用例矩阵

所有时间为受控虚拟时钟。题目不以真实 CPU 毫秒表现判分。

| 用例 | 输入或操作 | 预期 |
| --- | --- | --- |
| T01 单次 | 调用后前进 wait−1，再前进 1 | 恰好一次、参数正确 |
| T02 连续 | 样例 1 | 从最后一次调用计算等待 |
| T03 this | 两个对象先后调用同一 wrapped | 使用后一次对象作为 this |
| T04 参数 | 最后一次传入多个值，含 undefined | 原样保留全部位置 |
| T05 取消 | 样例 2；重复 cancel | 0 次，无多余计时器 |
| T06 flush | 样例 3；再 flush | 第一次返回结果，第二次 undefined |
| T07 空状态 | 从未调用，直接 cancel/flush | 无异常，无调用 |
| T08 零等待 | wait=0 后尚未推进时钟 | 不同步执行；推进定时器后执行 |
| T09 独立实例 | 两个包装器各排任务，只取消其一 | 另一个正常执行 |
| T10 校验 | fn 非函数，wait 负/NaN/小数/Infinity | 按合同抛错，不创建计时器 |
| T11 flush 异常 | fn 抛错；捕获后再次调用 wrapped | 错误透传，新调用仍能工作 |
| T12 回调重入 | fn 内再次安排 wrapped | 下一轮保留，不被本轮清理破坏 |
| T13 释放状态 | 执行或取消后检查公开可观察行为 | 不再迟到执行；不依赖私有变量断言 |
| T14 定时器异常 | harness 捕获 fn 在 timer 中的异常，再安排新调用 | 错误可见，包装器可继续使用 |

内存引用释放可在参考实现审阅中检查，不用不稳定 GC 时机做自动测试断言。

## 三层提示

1. **方向**：明确“当前等待的一次调用”由哪些状态组成。
2. **结构**：每次调用替换参数和上下文，旧计时器取消后重新安排。
3. **关键边界**：执行 fn 之前清除本轮状态；如果 fn 内重入，不能在执行后把下一轮状态也清掉。

## 参考解析结构

未来参考实现应解释：保存一份待执行上下文、复用一次执行/清理流程、取消与 flush 如何共享语义、为何清理发生在 fn 之前。调用包装器的工作量为 O(1)（不计参数复制与 fn 本身）；待执行状态仅保留最近一次参数与 this。

替代讨论：增加 leading/maxWait 将引入新的时间窗和边界，这不是当前题目要求。不能用第三方 debounce 直接替代作答；学习完成后可以对照工具库行为差异。

## 必须击败的错误方案

- 不取消旧定时器：T02/T05 失败。
- 只保存首次参数：T03/T04 失败。
- flush 后没清原定时器：T06 失败。
- 执行完才无条件清理：T12 失败。
