# 交接说明与决策记录

## 给下一位实现者

你接到的是设计资料包，以及已可运行的前端脚手架。请先读根目录 README 与设计总览，再继续实施；不要只看首页图就生成一个通用博客模板，也不要把功能清单压缩成几个卡片。

必须还原：浅色技术手册；六个一级入口；知识/练习/AI 关联；主动回忆与明确评分规则；草稿与笔记可靠保存；独立通过和参考完成区分；导出/恢复；完整状态与移动端。所有面向用户的系统文案及发布内容遵守 01 的词汇规则。

最初用户要求先设计；随后已明确授权搭建仓库骨架。现有代码仅覆盖路由、基础页面和目录展示。后续完整功能仍按 13 的阶段计划实施，部署需根据后续指令决定。

## 默认值与可更换项

可以不改变产品合同自行调整：文件内部组织、符合语义的图标库、经核验的兼容依赖版本、等价组件实现。品牌名属于低成本可替换项，暂按知序。

需要先写清变更再继续：内容裁剪、存储策略、评分公式、在线 AI、多人、公开提交执行、收集统计、云同步、付费服务、复杂发布授权。这些会改变行为、隐私或维护成本。

部署服务、真实域名与具体开发框架目前未指定，不阻塞设计。开发开始时记录选择即可；若选择的服务无法提供独立 runner 与所需响应头，则先解决 M0，不能削弱隔离来适配平台。

## 还原时常见偏差

- 首页变成大幅宣传页，用户找不到继续学习。
- 只有标签云和文章卡片，没有知识顺序、卡片与练习关系。
- 一滚到底就算掌握，统计比真实能力乐观。
- 打开参考答案后仍记录为独立通过。
- 仅展示正确状态，忽略保存失败、题目更新和跨页恢复。
- 手机简单缩小桌面三栏，正文与编辑器不可用。
- AI 页面只有提示词合集，没有验证、审阅、权限和时效信息。
- 用“以后再做备份”换取短期交付，导致私人笔记无法迁移。
- 静态假数据当真实用户记录；目录数量当正文数量。
