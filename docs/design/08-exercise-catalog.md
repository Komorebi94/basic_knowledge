# 动手练习目录与题目契约

## 范围

规划 40 题：E01—E24 为 P0、JavaScript 纯逻辑/异步运行环境；E25—E40 为 P1，包括 DOM、框架、类型与扩展算法。首版必须提供 24 题完整题面、骨架、测试、3 层提示、参考实现说明与复杂度分析。本次只设计契约，不编写答案实现。

难度：基础表示单一机制；进阶表示多个边界；挑战表示调度、身份或复杂数据结构。建议分钟用于安排时间，不作倒计时。

## 每题发布前必须补齐的合同

2026-10-15 内容纠错补充：上表保留完整 DOM、React、TypeScript 练习的规划目标；当前 E25—E40 在独立 JavaScript Worker 中运行。DOM/框架相关条目实际提供行为状态模型，E33 是属性投影、浅冻结与 Promise 吸收，E34 是事件名称和参数数量校验，E40 是分帧预算规划。公开目录使用实际题面的名称与说明，不将模型通过计作真实 DOM、Hook、编译器或后台帧调度验收。TypeScript 真实正负编译练习已补到 K03-05/06；React 真实挂载实验补到 K07，均为受审查作者示例，不扩大用户代码运行边界。

1. 输入输出、参数名称、返回值、错误类型、是否修改输入、是否支持 this。
2. 数据域与刻意不实现的能力；不能出题后才引入新要求。
3. 3 个可见样例、至少 8 个行为用例（基础题可 6 个，但必须有空/边界/失败）。
4. 初始骨架只定义接口和必要辅助类型，不泄露解法。
5. 三层提示、一个参考方案、一个可讨论替代方案、复杂度与反例。
6. 与稳定知识 ID 关联；标注运行环境、版本、时间预算。
7. 用例不仅运行参考实现，也必须击败至少两个典型错误方案。

接口文字仍有歧义时，内容作者先冻结详细题面和用例矩阵，再写实现，不能直接凭表格猜题。E01 的可直接制作样稿见 [防抖练习](examples/exercise-debounce.md)。

## 判题边界

客户端用例不是保密测试，用户可以查看；用途是学习反馈。性能复杂度通过参考分析和人工检查确认，不能用单次毫秒值可靠判定 O(n)。内存安全和恶意程序防护不由题目测试解决，运行器限制见 12。
