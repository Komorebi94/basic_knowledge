# 技术建议与实现边界

## 架构建议

推荐以 TypeScript + 组件式前端 + 静态内容构建实现。若没有团队既有约束，React + Vite 可作为默认候选；用 Vue 实现也必须保持相同产品行为。这里不锁未经核验的具体依赖版本，开发启动时选择相容稳定版本并记录锁文件。

个人知识站首版不要求 SSR、数据库服务器或账号系统。知识文章预构建，交互按需加载；必须支持深链接刷新。可以生成静态路径，也可以由部署服务正确回退应用入口，不能靠用户从首页点进去规避路由问题。

## 模块责任

| 模块 | 拥有的职责 | 不允许做的事 |
| --- | --- | --- |
| content | 内容校验、清单、关系、索引构建 | 读取私人学习数据 |
| learning | 阅读、复习、练习证据的领域规则 | 直接操作 DOM 或 UI 路由 |
| persistence | 事务、校验、并发版本、备份迁移 | 决定卡片应隔几天复习 |
| search | 查询规范化、排序、片段 | 默认上传笔记到外部 |
| runner-client | 运行会话、超时、消息校验 | 在主页面求值用户代码 |
| runner-host | 隔离工作环境、测试执行 | 获取主站笔记、数据库、凭据 |
| ui | 页面、组件、反馈、可访问性 | 重复实现调度公式与数据库规则 |

建议未来目录：src/app、src/features/{knowledge,practice,review,ai,personal}、src/domain、src/infrastructure、src/components、content、runner、tests。仅是责任边界，不要求把每一行逻辑切成文件。不提前创建空架构。

## 内容渲染

仓库内容经过构建校验后生成静态文章与索引。禁用任意 MDX 执行；图表与交互块必须有组件白名单和输入 Schema。禁止将正文 HTML 直接注入界面。所有外链仅允许 http/https，代码块始终作文本。

编辑器按进入 S06 后加载，阅读页不加载编辑器、测试工具或参考答案包。公共内容本来可查看，不把按需加载当成保密机制。

## JS 运行器：P0 必须先验证的技术点

运行器采用独立 origin 的静态页面与专用 Worker。主站只发送当前题目、代码快照和运行 ID；不得带入个人数据库、token、其他笔记、完整浏览器状态。

推荐流程：

1. 主站创建指向 runner origin 的 iframe；只允许所需脚本能力，不授予表单、弹窗、下载、顶层导航等权限。
2. runner origin 与主站不同；站点部署使用独立子域且无共享认证 cookie。若 runner 使用 allow-same-origin，是为了其 Worker 兼容，必须保持与主站跨 origin，不能部署成主站同源路径。
3. 本地开发可用两个固定端口形成不同 origin，站点只用 IndexedDB 存个人数据，不把 token 放在域 cookie 中。
4. runner 宿主创建静态 Worker 引导脚本，在 Worker 内执行用户代码与受审查测试；主页面和 iframe 主线程不运行用户代码。
5. iframe/Worker 的 CSP 分别设计：默认拒绝外部资源；connect-src 禁止网络；iframe 只允许自身静态脚本和指定 Worker；Worker 禁止再创建 Worker 和导入外部脚本。若执行方案需要动态求值，仅在隔离 Worker 对应策略放开必要能力。
6. 消息验证 event.source、精确 origin、随机会话 token、runId、Schema 和载荷长度；旧 runId 与多余消息丢弃，测试结果作为不可信数据处理。
7. 每次运行新建 Worker；停止、超时、路由离开都 terminate；下一次运行重新创建干净环境，不继承原型污染。

必须以浏览器实测确认 CSP 是否生效、Worker 能否创建、导入脚本与网络是否被阻断。不要用覆盖 fetch、冻结少数全局变量或“代码看起来安全”替代隔离。

默认每次执行 2,000 ms，题目可显式提高到最多 5,000 ms。使用主站独立计时器处理超时；后台页定时器可能被节流，产品不承诺硬实时。时间类题使用虚拟时钟，不为了等 1 秒真的阻塞一秒。

浏览器 Worker 不能提供可靠的硬内存配额，也不是面向敌对提交的服务器级沙箱。限制源码、消息和输出规模，及时终止；极端内存耗尽仍可能影响标签页。P0 定位本人学习，不接受公开陌生人提交。若未来要承接敌对代码，必须另立服务端隔离方案与安全评估。

## 运行协议

| 方向 | 消息 | 必需信息 |
| --- | --- | --- |
| runner → 主站 | ready | 协议版本、会话 token |
| 主站 → runner | run | runId、exerciseId、revision、codeRevision、代码快照、执行预算 |
| runner → 主站 | case-result | runId、caseId、状态、受限 expected/actual、耗时 |
| runner → 主站 | console | runId、level、受限文本 |
| runner → 主站 | done | runId、总数、通过数、状态 |
| 主站 → runner | stop | runId |
| runner → 主站 | error | runId、错误种类、净化后的信息 |

codeRevision 与结果必须一起返回。run 命令中的 exerciseId 必须存在于受信任清单，不允许任意加载 URL。停止期间仍到达的结果不得覆盖已停止状态。客户端测试不是防作弊系统，不能保证用户代码无法探查测试。

## 数据、搜索与性能

IndexedDB 通过单一存储适配层访问；搜索采用支持中文索引的客户端方案。具体库通过小样验证决定，不因偏好引入服务器。全文索引分块缓存，私人笔记索引单独构建，只在明确搜索私人内容时使用。

避免常驻轮询；首页统计由事件更新或进入页面时计算。大列表分页；长代码与超长结果截断。正文资源和个人数据分别版本化，不能更新缓存时清个人库。

## 部署与隐私

P0 默认本机或私有访问部署。若部署成公开静态站，公共文章与题目资源可被任何访客读取；本地保存不等于网站访问控制。想让整站仅本人可访问，需要在托管层增加访问限制并单独验收，不把前端路由拦截视为鉴权。

主站与 runner 的 origin、CSP、深链接回退、HTTPS、静态资源缓存策略是部署清单必填项。内容资源使用带版本标识的文件名；入口文档短缓存，避免应用版本与索引不匹配。P0 不承诺完整离线功能，网络中断时已加载页面与本地记录仍可使用，未缓存文章显示明确加载错误。

## 技术验证与退出条件

先做四个小验证：浏览器隔离运行、草稿保存恢复、备份事务替换、中文搜索。目标浏览器为实现时 Chrome/Edge/Firefox/Safari 当前及上一主要版本，移动端 iOS Safari/Android Chrome；锁定具体版本写入验收记录。

任何目标环境无法安全执行时显示“当前环境暂不支持运行”，保留编辑和代码下载；不得降级为主线程 eval。若主要桌面目标环境失败，运行能力属于未完成，不能发布为完整 P0。替代架构需更新本设计的决策记录。

P1 DOM/框架练习需要另做 DOM 宿主隔离、依赖版本和卸载验证；不要把 JS Worker 套上 iframe 就宣称支持完整 React/Vue。
