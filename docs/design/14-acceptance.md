## 运行隔离与内容安全

| ID | 验证 | 通过条件 |
| --- | --- | --- |
| SEC01 | 从 Worker 访问主站 DOM/数据库 | 无法获得主站 DOM、个人 IndexedDB 和凭据 |
| SEC02 | fetch/WebSocket/外部脚本/嵌套 Worker | 被 CSP/隔离策略阻断，宿主记录明确失败 |
| SEC03 | 伪造 origin/source/runId 或巨型消息 | 丢弃无效消息，页面不按消息执行 HTML/代码 |
| SEC04 | 输出循环对象、超长字符串、无限日志 | 安全序列化/截断；达到限制不导致主页面失控 |
| SEC05 | 前一次运行污染原型后再次执行 | 新 Worker 无上一轮污染 |
| SEC06 | 恶意 Markdown、javascript URL、导入载荷 | 净化或拒绝，不能从内容与备份进入执行路径 |
| SEC07 | 独立 runner origin 配置 | 主站与 runner 不同源、无共享认证、权限最小化 |

极端内存耗尽不在浏览器硬隔离保证范围内，必须在已知限制中写明；不能用测试通过声称抵御所有敌对代码。

## 视觉与可访问性

- 1440×1000、1024×768、768×1024、390×844、360×800 检查主要页面；320 CSS px 做回流检查。
- 阅读列宽、主色、字级、侧栏与按钮层级对齐 04 和静态图，不要求跨字体逐像素一致。
- 200% 缩放下无整页横向滚动，代码与表格区域可独立滚动。
- 只用键盘完成搜索、打开文章、编辑笔记、开始复习、评分、关闭弹层、运行题目。
- VoiceOver 或 NVDA 至少一种走查：输入名称、标题结构、评分状态、保存错误、运行摘要。
- 所有有效文字、控件和焦点符合 04 对比要求；自动检测后人工复核。
- 编辑器 Tab 可退出，不形成键盘陷阱；减少动态效果设置有效。
- 手机软键盘、安全区、横竖屏转换不遮住当前输入与主操作。

## 性能预算

这些是目标，不是本次实测结果。固定一台参考设备和网络条件记录，至少重复 5 次并报告分布，不挑最好的一次。

| 项目 | 目标 | 测量条件 |
| --- | --- | --- |
| 首页 LCP | ≤2.5 s | 生产构建、冷缓存、约 10 Mbps/100 ms RTT、移动 CPU 限速 |
| CLS | ≤0.1 | 首屏加载及首次数据恢复，避免统计卡高度跳动 |
| 交互响应 | 核心操作反馈 ≤200 ms | 不含人为输入和后台 Worker 运算；另评估 INP |
| 客户端搜索 | p95 ≤100 ms | 索引已加载，1,000 篇基准内容，100 个中英查询，排除防抖 |
| 输入到搜索结果 | p95 ≤300 ms | 包含 150 ms 防抖，组合输入结束后开始计时 |
| 阅读页初始 JS | gzip ≤250 KiB | 不含正文、搜索延迟包、编辑器、运行器 |
| 编辑保存状态 | ≤1 s 显示已保存 | 小于 20,000 字符笔记，正常 IndexedDB，含防抖 |

真实用户数据不足时，不能把实验室测试结果标成“全体用户 Core Web Vitals 已通过”。指标定义参见 [Web Vitals](https://web.dev/articles/vitals)。

## 内容与发布验收

检查 32 知识 +24 练习 +16 AI 的 P0 清单完整，至少 96 卡片；模板和案例可用。所有 published 内容满足 10，目录规划条目不冒充正文。所有链接和引用 ID 有效，用户界面与发布内容不含禁用宣传词，私人笔记例外规则见 01。

发布前填写：构建 ID、浏览器版本、部署 origin、CSP、检查命令与结果、真实截图、未通过项、数据恢复验证、已知限制。任何 P0 失败必须修复或明确作为未完成交付，不能自行改成 P1 藏掉。

## D14 阅读修订验收

- 知识与 AI 文章均无页内目录、来源核验模块或笔记编辑区；正文单栏。
- 闭包单元以 14 节讲解和 12 个原创可运行示例覆盖机制、共享/独立绑定、循环、TDZ、异步和资源清理；示例输出由 verify:closures 校验。
- 章节深链接和全文搜索仍可使用，桌面/平板/手机不出现整页横向溢出。
- 我的积累可选择文章编辑笔记；刷新恢复、冲突、同页切换文章/分类与跨页离开时保护输入，原笔记可导出与恢复。

## D15 全站内容写作验收

- 当前所有可读文章与后续新增正文均遵循 10 的深入教程标准，不能只在闭包单元讲透。
- 每篇按实际学习目标检查完整性，不强制复制闭包文章的章节数量；有问题、推导、可复现示例、逐步解释、失败边界和工程取舍。
- AI 方法包含贯穿案例、可填写合同、错误实现与审阅/验收证据；不把通用方法当成具体工具保证。
- verify:articles 校验全部仓库示例的预期输出，TypeScript 示例严格类型检查；故意错误的示例有明确解释。
- 稳定内容 ID、旧 URL、个人记录关联、完整目录、全文搜索与单栏阅读规则保留。
